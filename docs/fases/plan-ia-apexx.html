Reglas que no se rompen

Cinco límites para toda función de IA

El comprador nunca espera a un modeloCatálogo, ficha y carrito siguen en milisegundos. Lo que necesita un modelo se calcula al escribir o en paneles donde unos segundos son aceptables.
La IA no inventa datos de comercioPrecio, existencias, envío, impuestos y estado del pedido salen siempre del sistema. El modelo redacta, ordena y propone.
Una sola base, sin indexador aparteVectores en Postgres con RLS por tienda (sin depender de extensiones); copia cuantizada int8 en memoria. El outbox mantiene todo al día.
Todo se puede deshacerCada sugerencia aplicada queda en la auditoría con modelo, versión del prompt y fuentes, y se revierte como un cambio masivo.
El contenido recuperado es datoDescripciones, opiniones y PDF de clientes pueden traer instrucciones maliciosas: se citan, nunca se obedecen. Escribir requiere aprobación.

Arquitectura

El mismo camino que ya usa el catálogo

Escritura
Panel, API o importación→Postgres (fuente de verdad)→Evento en outbox con posición seq
Tienda (ms)
Proyección en memoria→Léxico + vector int8→Fusión RRF→Re-ranking con señales
Trabajadores IA
Fragmentar + contexto (por lotes)→Embeddings → ai_chunks·Relaciones → kg_edges
Asistentes (s)
Herramientas del sistema→CRAG: evaluar, corregir, citar→Respuesta estructurada
Si el proveedor de embeddings falla, la tienda sigue con búsqueda léxica y la cola reintenta sola. Si una fuente cambia, su hash marca los fragmentos para regenerarse.
